    Review of presto_pipeline against this study (working note)¶

    Working note, 24 Nov 2026. Not part of the site navigation.

    Repository reviewed: zlab-foss/presto_pipeline, commit e46418c (31 May 2026; last push 18 Aug 2026), 22 commits, description "Presto — Irrigation + LandCover Integration". A shallow clone is kept outside this repository at ../presto_pipeline (next to irrigated_area_mapping_code/). File references below (file:line) point into that clone. The code was read, not run; the checkpoints were inspected with pickletools (no unpickling).

    1. Summary¶

    presto_pipeline is an inference pipeline that applies an already fine-tuned Presto classifier (irrigated vs rainfed) to the pixels of an area of interest. Imagery is downloaded per tile from Google Earth Engine, either Sentinel-2 RGB+NIR with Sentinel-1 VV/VH, or Landsat with ERA5-Land; pixels outside the Esri 10 m LULC cropland class are skipped; predictions are written as uint8 GeoTIFFs per tile. A second script applies a small MLP to Google's AlphaEarth annual embeddings. The repository contains no training script, no training labels and no accuracy figures, and it has no licence.

    For this study it is not a replacement for any component: its data access (Earth Engine, QA60 cloud mask, EPSG:4326 grid, Sentinel-1) contradicts decisions D9, D14 and D18, and its Presto inputs deviate from the pretraining format in four respects (Section 4). Two ideas are worth adopting for the mapping phase: skipping non-cropland pixels before the encoder, and writing never-observed pixels as nodata.

    3. Relevance to the research questions and the mapping phase¶

    Part of this study Relevance Reason
    RQ1 frozen GeoFMs vs baseline low presto_pipeline fine-tunes Presto with Sentinel-1 or Landsat+ERA5 on undisclosed labels with no reported accuracy; there is nothing to compare against E04 (frozen Presto, Sentinel-2 only, macro-F1 0.903 [0.848, 0.942], E04)
    RQ2 frozen vs fine-tuned low to moderate it is a working example of full fine-tuning of Presto with an MLP head, i.e. the strategy that E05 tests for Prithvi; it gives no evidence, since no evaluation is published
    RQ3 temporal consistency, map series low one model per year is applied; there is no multi-year assessment
    RQ4 second region none directly its regions (Karkheh, Lake Urmia/Oroumieh, Anzali) are not study areas here; the released weights could in principle be applied to Morocco as an external model, but they need Sentinel-1 (contradicts D14) and their training data are unknown
    RQ5 fusion marginal the AlphaEarth path shows a ready-made annual embedding (64-d) that could be a further input to a fusion test; it is outside the six encoders selected in Foundation models
    Phase 5 wall-to-wall maps moderate (ideas, not code) the per-tile structure "download → tensor → mask → infer → GeoTIFF with nodata" mirrors the planned workflow (Phase 5); the mask-before-inference step is directly useful (Section 5)

    3.1 Could it replace or simplify a part of this pipeline?¶

    Component here presto_pipeline equivalent Verdict
    Sentinel-2 monthly composites from STAC per 10.24 km block (s2_download/, D18) Earth Engine + geedim, per tile, QA60, scenes ≤ 10% cloud, EPSG:4326 No. D18 moved away from Earth Engine because of the 48 MB request limit and about 40 h per year on one stream; QA60 is the mask that D9 replaced by Cloud Score+ (here SCL in the STAC path); the 10%-cloud scene filter discards many partly clear scenes; a geographic grid does not match the projected 128 px tiles
    Per-pixel Presto embeddings (pixelwise_run/encoders.py, PrestoEncoder) PrestoTensorBuilder + Encoder No. The design is the same (17-channel tensor, constant mask, temporal interpolation, NDVI, Dynamic World = 9), but this study's implementation already follows the pretraining format more closely (Section 4)
    Mapping at scale (tiling, inference, GeoTIFF output) main.py, shap_tiler.py, merge_tiffs.py Partly, as a pattern. Per-tile skip-if-exists and resume (skip_download, tile_idx_resume, main.py:361-387, main.py:582-585) and nodata handling are simple and robust; the code itself assumes Earth Engine inputs and a pixel-only classifier without a spatial head, so it cannot drive the UPerNet models of E04

    Month of the first time step calendar month of the first composite start_month − 1 (September → 8) (encoders.py, PrestoEncoder.forward) 0 (January) for every tile (model/presto.py:217, model/presto.py:247-252, no month passed in main.py:489), although the series starts in September (pysentinel.py:71)
    Missing months masked tokens in pretraining linear interpolation in time; never-observed pixels → 0 linear interpolation, ends filled from the nearest valid month (preprocess_utils.py:9-126); never-observed pixels → nodata in the map (main.py:403-431)
    Encoder weights — frozen (E04) fine-tuned (freeze_encoder = False in both checkpoints)

    Because the encoder was fine-tuned, a consistent deviation at training and inference time is partly absorbed by the fine-tuning. The deviations nevertheless reduce how much of the pretrained representation is reused: the S2_RGB projection, the S1 projection, the location token and the month encoding all receive inputs with a different meaning from pretraining. A frozen use of these settings, as in E04, would not be valid. None of these points contradicts the description of Presto in Foundation models; the pretraining format stated there (Sentinel-2 / 10,000, location as latitude and longitude, month and band-group encodings) agrees with the upstream code and with PrestoEncoder.

    5. Worth borrowing¶

    1. Mask before the encoder in the mapping phase. Pixels outside the chosen cropland mask are removed before inference, and a tile without cropland skips the model (main.py:433-485). For Presto and TESSERA, which cost 14.1 and 24.7 GPU hours in E04 because every pixel is encoded, encoding only mask pixels (and giving the others a zero embedding before the UPerNet head) could reduce mapping time roughly in proportion to the non-cropland share. The effect of zero embeddings on the spatial head at mask edges would have to be checked on the labelled tiles first. This fits the open choice of mask in D19.
    2. Explicit nodata for never-observed pixels. Pixels without any clear month are written as nodata instead of being classified from a zero vector (main.py:403-431); this study's fill_time_torch sets them to 0 and still classifies them. For the maps, a separate nodata value (and a per-pixel count of clear months) would make such pixels visible in the accuracy assessment.
    3. Resume and skip-if-exists per tile (main.py:361-387, main.py:582-585), already partly present in s2_download/; a check that the same logic exists for the inference step of Phase 5.
    4. Esri LULC as one more mask candidate, aligned to the image grid with nearest-neighbour resampling (main.py:184-271, utils/utils.py). Esri LULC was one of the four products of the union mask (D17), which is now archived; the maps use the annual Dynamic World cropland only, so this point no longer applies.

    6. Risks and mismatches¶

    • No licence. Without a licence the code cannot be reused or redistributed; ideas can be reimplemented. Its model code also omits the MIT notice of the upstream Presto code.
    • No evaluation. No training data, labels, validation design or accuracy are published; the released irrigation weights cannot serve as a reference product or a baseline.
    • Input deviations (Section 4): red/blue swap, non-standard scaling, swapped latitude and longitude, fixed month index 0. Copying preprocess.py into this study would introduce these errors.
    • Silent fallbacks. A failed LULC download leads to inference on all pixels (main.py:267-271); a failed downloader initialisation is reported as "VPN not connected" and continues (main.py:545-549).
    • Incomplete release. Presto_S2Full_S1.pt is referenced (main.py:168) but absent; the README describes a group_flags option of PrestoTensorBuilder that the code does not have (README.md:145-156 vs preprocess.py:84); get_data.py uses command-line arguments.
    • Sensor and access. Sentinel-1 input contradicts D14; Earth Engine per-tile download contradicts D18.

    7. Recommendation¶

    Do not adopt the repository or its weights. Record it as related work only if it becomes citable (it has no paper or licence). In Phase 5, reimplement two ideas in this study's own code: (1) restrict per-pixel encoding to the chosen cropland mask, after a test on the labelled tiles, and (2) write never-observed pixels as nodata. No change to E04 or to PrestoEncoder is indicated; the comparison confirms that this study's Presto input follows the pretraining format.
